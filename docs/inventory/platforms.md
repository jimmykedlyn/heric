# Platform differences

Scope: every per-OS branch in the original Electron app and CLI. Paths are relative to `D:\Projects\Heric\Insomnia`; citations are `packages/...:line`. Statements about what Electron/OS APIs do internally (safeStorage backends, Chromium proxy resolution) are labelled "Electron/OS behavior" — they are consequences of APIs used in the cited code, not code present in the repo.

## Paths

- **Data root relocation (all platforms).** `packages/insomnia/src/entry.main.ts:54-58`:
  `dataPath = process.env.INSOMNIA_DATA_PATH || path.join(app.getPath('userData'), '../', isDevelopment() ? 'insomnia-app' : userDataFolder)`, then `app.setPath('userData', dataPath)`. `userDataFolder` = `"Insomnia"` (`packages/insomnia/config/config.json:4`; also `appId`, `productName` at lines 3, 6). Effect: the app stores data in the sibling folder of Electron's default:
  - Windows: `%APPDATA%\Insomnia` (Electron default would be `%APPDATA%\<name>`)
  - macOS: `~/Library/Application Support/Insomnia`
  - Linux: `~/.config/Insomnia` (Electron default follows `$XDG_CONFIG_HOME`)
  - Dev builds: `insomnia-app` instead (`entry.main.ts:56`).
  The relocation happens before Sentry init specifically so Chromium's own storage follows it (`entry.main.ts:50-53` comment).
- **Everything derived from the data root** uses `process.env['INSOMNIA_DATA_PATH'] || app.getPath('userData')`: DB (`src/main/database.main.ts:8`), `responses/` (`src/main/ipc/main.ts:194`; `src/main/network/curl.ts:151`, `websocket.ts:193`, `socket-io.ts:277`, `mcp/common.ts:123`), `localStorage/` JSON store (`src/main/electron-storage.ts:8-9`, `entry.main.ts:61`), `plugins/` (`src/main/create-plugin.ts:32`, `src/main/install-plugin.ts:92`), `llms/` (`src/main/llm-config-service.ts:90`), `version-control/git` (`src/main/git-service.ts:401`, `4020`), spectral cache (`src/main/spectral-ruleset-cache.ts:20`), response files (`runtimes/network/network-adapter.node.ts:36`), plugin index (`src/plugins/index.ts:436`).
- **Logs** are OS-specific via electron-log's `libraryDefaultDir` (`src/main/log.ts:29-34`): on Linux that is the XDG state dir, on macOS `~/Library/Logs`, on Windows `%APPDATA%\<name>\logs` (electron-log behavior). File logging is disabled in development (`src/main/log.ts:22-24`); rotation at 10 MB and truncation on start (`log.ts:39-45`).
- **Renderer path functions** are proxied to Node on the main side (`src/main/ipc/path.ts:6-18` exports `path.basename/dirname/join/resolve` over IPC), so Windows separators are computed by Node, not the renderer. A tiny shim `src/path-shim.ts:1` re-implements `extname` only.
- **`app.getPath` bridge**: renderer and plugin preloads expose only `desktop` path through `app.getPath` (`src/main/ipc/electron.ts:490-492`; plugin/API context restricts to `'desktop'`: `src/plugins/context/app.ts:47-50`). Menu items "Show App Data/Logs Folder" use `shell.showItemInFolder` (`src/main/window-utils.ts:540, 546`). Dev menu screenshot is written to `app.getPath('desktop')` (`window-utils.ts:660-667`).
- **Inso CLI** reproduces Electron's `getPath('userData')` itself, per-platform (`packages/insomnia-inso/src/util.ts:9-24`):
  - darwin: `~/Library/Application Support/<app>`
  - win32: `%APPDATA%` (fallback `~/AppData/Roaming`)
  - linux: `$XDG_DATA_HOME` else `~/.config` (note: `.config`, i.e. config, not data — mismatch with XDG spec, but intentional precedent)
  - anything else throws `Unsupported platform`. Product name comes from build-time env `DEFAULT_APP_NAME` (`util.ts:26-31`, injected in `packages/insomnia-inso/esbuild.ts:51` as `Insomnia` / `insomnia-app`).
- **Plugin search paths** are split on `:` only (`src/plugins/index.ts:423-427`) — a Windows drive letter (`C:\...`) would break this list; `~/` is expanded via `process.env['HOME']` (`plugins/index.ts:427-431`), which is typically unset on Windows.
- **Windows path escaping in environments**: `{% file '...' %}` tags in environment JSON are double-escaped on Windows before parse and unescaped after serialize (`src/ui/components/editors/environment-editor.tsx:46-47, 91-92, 127-138`) so backslashes survive `orderedJSON` round-trips (references issue #5754).
- **Path containment checks** use `path.sep`/`path.resolve`, so they are separator-aware but OS-agnostic (`src/main/ipc/path-guard.ts:6-18`; `src/main/secure-read-file.ts:12-22`). Allowed roots: `os.tmpdir()`, `<data>/responses`, `<data>/version-control`, plus user allow-list (`secure-read-file.ts:36-45`).
- **Reserved DB file read guard** compares `${dev}:${ino}` identity (`secure-read-file.ts:61-76`) — inode numbers are meaningful on POSIX; on Windows Node reports file-index-based `ino`, so hard-link aliasing is still detected.

## Credentials and secrets

- **Secret storage = Electron `safeStorage` into a JSON file**, not `keytar`. `src/main/ipc/secret-storage.ts:54-70`:
  - `encryptString`: if `safeStorage.isEncryptionAvailable()` → `safeStorage.encryptString(raw).toString('hex')`, else returns the raw plaintext.
  - `decryptString`: builds `Buffer.from(cipherText,'hex')`; if encryption available tries `safeStorage.decryptString` and **falls back to returning the ciphertext string itself** on failure (`secret-storage.ts:61-70`).
  - Values are stored through `ElectronStorage` (`<data>/localStorage` files) under `setSecret/getSecret/deleteSecret` (`secret-storage.ts:20-52`).
  - Electron/OS behavior behind `safeStorage`: Windows DPAPI (per-user), macOS Keychain (app-specific key), Linux libsecret/kwallet; when no keyring is available Electron reports encryption unavailable and the code silently stores plaintext.
  - Edge case: hex round-trip means a plaintext fallback that happens to be valid hex is indistinguishable from ciphertext; a decrypt failure returns that hex string to callers.
- **Consumers**: vault key (`vault_<accountId>` key name, `src/common/utils/vault.ts:49-65`), only saved when the user opts in (`saveVaultKeyLocally`, `vault.ts:51-57`; UI toggle at `src/ui/components/settings/vault-key-panel.tsx:186`). Playwright tests bypass encryption by reading `INSOMNIA_VAULT_KEY` env (`vault.ts:32-36`).
- **Runtime adapter split**: node adapter imports the electron `safeStorage` module directly (`src/runtimes/secret-storage/secret-storage-adapter.node.ts:8-16`); renderer adapter forwards over IPC (`.../secret-storage-adapter.renderer.ts:1-5`).
- **Git credentials**: the "native" provider shells out to `git credential fill` and lets the OS helper (macOS Keychain, Windows Credential Manager/GCM, libsecret) resolve — nothing is stored in Insomnia (`src/sync/git/providers/native.ts:12-30, 62-150`). Child process uses `windowsHide: true` (`native.ts:93`). Other providers store tokens in the NeDB DB.
- **OAuth window**: child `BrowserWindow` with its own session; TLS validation is toggled by `validateAuthSSL` via `setCertificateVerifyProc` → `BLIND_TRUST` when disabled (`src/main/authorize-user-in-window.ts:130-137`), and the user's proxy can be applied to that session (`authorize-user-in-window.ts:143-149`).
- **Platform is exposed to sandboxed plugins/scripts** through a cloned value: main preload `process: { platform }` (`src/entry.preload.ts:437-441`), plugin-window preload (`src/entry.plugin-window-preload.ts:4-8`), unified accessor `platform/isMac/isWindows/isLinux` (`packages/insomnia-data/common-src/platform.ts:31-34`) with default `'linux'` when neither `window.app.process` nor `process` exists (`platform.ts:28`). Templating sandbox injects `appInfo.platform` from `process.platform` (`src/main/templating-worker-database.ts:422` etc.), exposed as a frozen `process.platform` stub (`src/templating/sandbox/sandbox-globals.ts:143-149`), with fixtures hardcoding `'linux'` (`sandbox-surface.ts:149, 355`). Plugin `app.getInfo()` returns `platform` (`src/plugins/context/app.ts:52`).

## TLS certificates

- **Request engine is libcurl** for HTTP(S); every instance sets `CURLOPT_SSL_OPTIONS = NativeCa` — "Use the system's native CA store" (`src/main/network/libcurl-promise.ts:377-378`). Electron/libcurl behavior: Secure Transport on macOS (keychain), schannel on Windows, OpenSSL/GnuTLS + system bundle on Linux. Comment at `libcurl-promise.ts:373` notes the fallback wording ("or leave unset to use keychain on macOS").
- **Workspace CA cert** overrides the store: `CAINFO_BLOB` with the file content read from disk (`libcurl-promise.ts:374-376`; loading in `src/main/network/curl.ts:165-167, 202`).
- **Client certificates** (mTLS) from the workspace: PEM (`SSLCERT` + `SSLCERTTYPE=PEM`, key via `SSLKEY`, passphrase via `KEYPASSWD`) or P12/PFX (`SSLCERTTYPE=P12`) (`libcurl-promise.ts:379-407`), each path gated by `isPathAllowed` against `settings.dataFolders` (`libcurl-promise.ts:382-403`).
- **SSL verification toggle**: `settings.validateSSL` default `true` (`packages/insomnia-data/src/models/settings.ts:84`); when off, `SSL_VERIFYHOST=0` and `SSL_VERIFYPEER=0` (`libcurl-promise.ts:459-465`).
- **WebSocket/Socket.IO use Node's TLS, not the OS store**: CA = workspace CA PEM else `tls.rootCertificates.join('\n')` (`src/main/network/websocket.ts:211-215`; `src/main/network/socket-io.ts:190-195`). Consequence: OS-installed enterprise roots are honoured by HTTP(S) requests but *not* by WS/SIO unless the workspace CA is set — a cross-platform behavioural divergence from libcurl's NativeCa.
- **OAuth SSE forwarding** also uses `NativeCa` (`src/main/api.protocol.ts:74`).
- **gRPC** uses `ChannelCredentials.createSsl(Buffer.from(caCertificate))` with `rejectUnauthorized` from settings (`src/main/ipc/grpc.ts:249, 408`); no OS-store fallback is visible in that path.
- **Electron `net.fetch`** (used by analytics/Sentry/git/OAuth fetch and the `insomnia-fetch` implementation) picks up OS certs and the session proxy "like the renderer; node fetch does neither" (`src/entry.main.ts:72-76`).
- **Plugin install trusted CA**: a user-selected bundle file (`pluginNodeExtraCerts`, accepted `.pem/.crt/.cer/.p12` — `src/common/constants.ts:89`) is passed to the yarn child process as `NODE_EXTRA_CA_CERTS` (`src/main/install-plugin.ts:443-445`), UI at `src/ui/components/settings/plugins.tsx:285-311`. The same setting is *not* applied to app requests.

## Proxy

- **System proxy detection** is delegated to Chromium: `session.defaultSession.resolveProxy(url)` (library HTTP/SSE: `src/main/api.protocol.ts:61`; requests when `settings.proxyEnabled` is false: `src/main/network/libcurl-promise.ts:421-428`). Returned PAC string parsed by `parseResolvedProxy` (`libcurl-promise.ts:291-341`): first entry only, supports `PROXY/HTTP`, `HTTPS`, `SOCKS/SOCKS4`, `SOCKS5`; `DIRECT` → null → no proxy. Anything else → null (silent direct). Per-OS semantics are Chromium's (WinINet/PAC, macOS SystemConfiguration, Linux env/GNOME).
- **Session-level proxy** (renderer, Electron `net.fetch`, analytics): `src/main/proxy.ts:72-113`. With `proxyEnabled`, builds `http=host;https=host` from `httpProxy`/`httpsProxy`, bypass list = `noProxy` plus first-party hosts unless `proxyScope === 'all'` (`proxy.ts:94-102`), mode `fixed_servers`; on parse failure or disabled, resets to mode `system` (`proxy.ts:104-113`). Watched live on settings change (`proxy.ts:116-135`), applied at startup before backup (`entry.main.ts:144-150`).
- **`proxyScope`** values `requests` (default; app's own traffic direct) and `all` (`packages/insomnia-data/common-src/settings.ts:92-98`; defaults at `packages/insomnia-data/src/models/settings.ts:59-72`).
- **libcurl path** (actual user requests) uses the configured proxy with `PROXYAUTH=Any`, and passes raw `noProxy` to `CURLOPT_NOPROXY` so IP/CIDR entries work (`libcurl-promise.ts:436-450`); host matching helper `shouldBypassProxyForHost` supports exact and leading-dot suffixes only (`libcurl-promise.ts:664-681`). If `proxyEnabled` is false the libcurl path independently re-resolves the *system* proxy (`libcurl-promise.ts:421-433`).
- **Git sync** creates a dedicated `git-sync-direct` partition and sets `mode:'direct'` when `proxyEnabled && proxyScope !== 'all'`; otherwise `electron.net.fetch` (system/session proxy) (`src/sync/git/http-client.ts:66-84`).
- **Plugin install (yarn child)** cannot see the Electron session, so `HTTP_PROXY/HTTPS_PROXY/NO_PROXY` are built from settings (`src/main/install-plugin.ts:449-458, 472-491`); default npm registry is bypassed unless scope `all`.
- **OAuth popup window** gets its own `setProxy` with the raw `httpProxy/httpsProxy` values (no `setDefaultProtocol` normalization, unlike `proxy.ts`) (`src/main/authorize-user-in-window.ts:143-149`).

## Menus and shortcuts

- **Menu ownership differs by OS**: `isMac` → `Menu.setApplicationMenu(menu)`, else `mainBrowserWindow.setMenu(menu)` — explicit comment "setMenu only works for Windows and Linux" (`src/main/window-utils.ts:793-799`). The menu is rebuilt per window, so each window has its own on Windows/Linux (`window-utils.ts:45-70` keeps debug-mode items in sync across windows).
- **Template**: Application / File(New Window) / Edit / View / Window / Tools / Help (`window-utils.ts:768-787`), plus Developer menu when `isDevelopment()` or `INSOMNIA_FORCE_DEBUG` (`window-utils.ts:789-791`).
- **macOS-only**: Application submenu with Preferences, Changelog, `hide`, `hideothers`, Quit; and About/Check-for-updates inserted at the top of the Application menu (`window-utils.ts:320-353, 608-624`). **Windows/Linux**: About + Check for updates are appended to Help (`window-utils.ts:625-642`); Window menu gains Close only on macOS (`window-utils.ts:500-509`); Help & Support accelerator `F1` only off macOS (`window-utils.ts:516-519`); About dialog button order is `[Copy, OK]` on Linux, `[OK, Copy]` elsewhere (`window-utils.ts:577-581`).
- **Mnemonics**: `MNEMONIC_SYM = isMac ? '' : '&'` (`src/common/constants.ts:103`), interpolated into every label so Windows/Linux get `&File`-style access keys.
- **Menu bar visibility** setting is hidden on macOS (`src/ui/components/settings/general.tsx:70`), default `autoHideMenuBar: false` (`packages/insomnia-data/src/models/settings.ts:31`), pushed to all windows (`src/ui/hooks/use-settings-side-effects.ts:29`; main handler `src/main/ipc/electron.ts:442-450`).
- **Native context menus**: `electron-context-menu` installed globally on `web-contents-created` (webviews get a window-scoped instance) (`src/entry.main.ts:89-95`). Renderer-driven context menus popup via `Menu.buildFromTemplate(...).popup()` (`src/main/ipc/electron.ts:499-512`).
- **Keyboard model**: separate `macKeys` and `winLinuxKeys` per action in the default registry (`packages/insomnia-data/common-src/hotkeys.ts:51-...`); `getPlatformKeyCombinations` selects by `isMac` (`hotkeys.ts:212-218`); display uses `⌘⌥⇧⌃` on macOS and `Ctrl/Alt/Shift`, `Win` (Windows) or `Super` (Linux) for meta (`hotkeys.ts:272-301`); macOS joins with space, others with ` + ` (`hotkeys.ts:249-255`), macOS order Ctrl, Alt, Shift, Cmd; others Meta, Ctrl, Alt, Shift (`hotkeys.ts:318-344`). Primary click = meta on macOS, ctrl elsewhere (`src/ui/utils.ts:5-7`). CodeMirror keymaps use `Cmd-` on macOS, `Ctrl-` elsewhere (`src/ui/components/.client/codemirror/code-editor.tsx:284-291`; `one-line-editor.tsx:212`). Global accelerators use `CmdOrCtrl` (`window-utils.ts:349, 363, 368, 380-396, 409-419`).
- **Menu accelerators use `role`s for OS integration**: cut/copy/paste/selectAll/minimize/togglefullscreen/hide/hideothers (`window-utils.ts:338-406, 488-509`); Undo/Redo are deliberately *not* roles — they route to the renderer (`window-utils.ts:358-375`).
- **Window chrome is identical on all OSes**: standard frame, no `titleBarStyle`/`trafficLightPosition`/vibrancy anywhere; `acceptFirstMouse: true` (macOS-only no-op elsewhere) and a 16px PNG window icon (`src/main/window-utils.ts:227-251`). `BrowserWindow` bounds are clamped to a visible display (`window-utils.ts:210-225`).
- **App menu "Preferences"** on macOS has no accelerator in the template; the actual `Cmd+,`/`Ctrl+,` binding comes from the renderer hotkey registry (`hotkeys.ts:64-67`) — macOS uses ⌘, while Win/Linux use Ctrl+, (smoke test confirms: `packages/insomnia-smoke-test/playwright/pages/components/statusbar.ts:26`).

## Deep links and protocol handlers

- **Scheme registration**: production scheme `insomnia://`, dev scheme `insomnia-dev://` (`src/entry.main.ts:172`). `app.setAsDefaultProtocolClient` at startup; in dev it passes `process.execPath` plus rewritten argv (`.` → absolute cwd) so the Electron binary is the handler (`entry.main.ts:173-190`). Failure path logs, then probes `isDefaultProtocolClient` and `getApplicationNameForProtocol` with an explicit note that `getApplicationInfoForProtocol` is unavailable on Linux (`entry.main.ts:191-213`).
- **Packaging declares the scheme** for all three OSes via electron-builder `protocols` (`packages/insomnia/electron-builder.config.js:12-19`).
- **Receiving URLs**:
  - macOS: `app.on('open-url')` (`entry.main.ts:313-315`).
  - Windows/Linux: single-instance lock + `app.on('second-instance')`, which restores/focuses the window and forwards the last CLI arg (`entry.main.ts:277-297`).
  - Cold start: argv after a hidden-window "halfSecondAfterAppStart" ping (`entry.main.ts:263-272`).
  - macOS Finder folder open: `app.on('open-file')`, converted to an open-folder deep link only if the path is an existing directory (`entry.main.ts:318-324`, helper `toOpenFolderDeepLink` `entry.main.ts:244-259`).
  - Renderer-originated: `ipcMainOn('openDeepLink')` (`entry.main.ts:325-327`).
  - All of this is skipped when `PLAYWRIGHT_TEST` is set to allow parallel e2e (`entry.main.ts:275`).
- **Forwarding to renderer**: `window.webContents.send('shell:open', url)` (`entry.main.ts:271, 295, 310`). Parsing: `parseDeepLinkUrl` (`src/common/import-deep-link.ts:6-24`) strips query, normalizes `insomniadev://` → `insomnia://` in dev. Handled routes: `insomnia://app/import` (+ `uri/mcp/curl/clipboard/file` params, `import-deep-link.ts:64-100`), `insomnia://app/auth/login`, `insomnia://app/alert`, `insomnia://app/open-folder` (`src/root.tsx:105-120, 448-479`). If signed out, open-folder/import links are queued in `sessionStorage.pendingDeepLinkAfterAuthorize` and replayed after login (`root.tsx:467-477, 760-769`).
- **Edge cases (documented in code)**: second-instance forwards `args.slice(-1).join(',')` — only the last argument survives (`entry.main.ts:291-297`); cold-start forwards `args.join(',')` (`entry.main.ts:271`). Non-folder absolute paths in argv are passed to the renderer as if they were URLs and simply fail parsing. The handler registration is best-effort: a non-folders second arg (e.g. `--flag`) becomes `shell:open` payload.
- **Custom internal protocols (not OS-visible)**: privileged schemes `insomnia-event-source`, plus `http`/`https` and `insomnia-templating-worker-database` interceptors (`src/main/api.protocol.ts:18-45, 52-166`), used so renderer fetch can stream SSE through libcurl and read template DB. Bypass with `bypassCustomProtocolHandlers` in `net.fetch` calls (`entry.main.ts:74-76`; `api.protocol.ts:146-161`).

## Packaging and updates

- **electron-builder config** `packages/insomnia/electron-builder.config.js`:
  - Common: `appId: com.insomnia.app`, `npmRebuild: false`, files from `./build`, `main: entry.main.min.js`, extra resource `bin/yarn-standalone.js` (lines 10-36). Binary prefix `Insomnia.Core` for artifact names (line 1).
  - **macOS** (39-97): hardened runtime, entitlements `build/static/entitlements.mac.inherit.plist` (allow-jit, allow-unsigned-executable-memory; dyld env and library validation disabled) (`src/static/entitlements.mac.inherit.plist:5-13`), universal dmg+zip, `mergeASARs:false`, `x64ArchFiles:'*'` (bundle universal binaries from x64 node_modules), `NSLocalNetworkUsageDescription`, `CFBundleDocumentTypes` for `public.folder` (Open With → folder as git project), `notarize: true`. `asarUnpack` lists node-libcurl, node-llama-cpp and reflink binaries for every platform.
  - **Windows** (116-134): targets `nsis` (x64) and `squirrel`; signing hook `./customSign.js` with DigiCert `smctl` (`customSign.js:16-43`, skipped when env vars absent); generic publish provider `https://updates.insomnia.rest/updates/win/`; `generateUpdatesFilesForAllChannels: true`.
  - **NSIS** (136-153): per-user selectable (`oneClick:false`, `selectPerMachineByDefault:true`), custom include `scripts/nsisInstall.nsh`, desktop+start-menu shortcuts, `deleteAppDataOnUninstall:false`. `nsisInstall.nsh:1-16` detects a pre-existing Squirrel install at `$PROFILE\AppData\Local\insomnia\Update.exe` and runs its `--uninstall -s`; `nsisInstall.nsh:17-25` writes `installer-info.json {installer:"nsis"}` into `$INSTDIR`, consumed at runtime (`src/main/updates.ts:193-209`).
  - **Linux** (158-197): AppImage, deb, tar.gz, rpm, snap (base `core22`), executable `insomnia`, desktop entry, RPM `_build_id_links none` to avoid fpm build-id collisions.
  - Build-target override via `BUILD_TARGETS` env + `PLATFORM_MAP` (`electron-builder.config.js:202-213`), used by CI for Linux ARM64.
- **Windows secure wrapper**: a C++ launcher replaces `Insomnia.exe` to harden DLL search (CVE-2025-1353 / local search-path vuln). It sets `ProcessSignaturePolicy` and `ProcessImageLoadPolicy` mitigation policies (`src/cpp/insomnia.cpp:152-179`), is compiled by `build-secure-wrapper.sh` (renames original to `insomnia.dll`/`Insomnia-origin-<ver>.exe`, windres+g++ static build, then repackages), and is a build step in CI (`.github/workflows/release-build.yml:169-172`). The updater contains a compensating workaround: on Windows it spawns `Update.exe --processStartAndWait Insomnia.exe` and quits instead of `autoUpdater.quitAndInstall()` (`src/main/updates.ts:79-96`).
- **Squirrel lifecycle**: on Windows only, `--squirrel-install/-uninstall` create/remove shortcuts via `Update.exe`; `--squirrel-updated/-obsolete` quit (`src/main/squirrel-startup.ts:15-49`); invoked before app ready (`entry.main.ts:79-82`).
- **Update backend**: two implementations — Electron `autoUpdater` (legacy/Squirrel, feed `updates/win` on Windows and `builds/check/mac` otherwise) and `electron-updater` for NSIS installs (differential download disabled, channel from settings) (`src/main/updates.ts:45-56, 99-102, 211-223`). Feed URL override `INSOMNIA_UPDATES_URL` (`updates.ts:44`).
- **Update gating**: disabled on Linux, on Windows when `PORTABLE_EXECUTABLE_DIR` is set, when `INSOMNIA_DISABLE_AUTOMATIC_UPDATES` is set, and in development unless `ALLOW_UPDATES_IN_DEV` (`src/main/updates.ts:18-42`); renderer mirror `updatesSupported()` (`src/common/constants.ts:59-69`) hides the update section and shows notification-only settings instead (`src/ui/components/settings/general.tsx:280-310`). Interval constant is 24 h (`src/common/constants.ts:87`) though the surrounding comment says 3 h (`src/main/updates.ts:111`).
- **CI** `.github/workflows/release-build.yml:53-64`: matrix `macos-15-large` (Developer ID certs), `windows-latest` (DigiCert SM, secure wrapper at 169-172, sign+repackage at 184-213, Squirrel signature verification at 217), `ubuntu-24.04` (x64 at 104; ARM64 entry commented out at 63-65, guarded by `runner.arch` and `BUILD_TARGETS: AppImage,tar.gz` at 96-110). macOS job also disables port-443 traffic to work around a notarization stapling issue (111-115). Inso CLI is packaged with `@yao-pkg/pkg` (host-only target, step at 253) and on macOS is code-signed + pkged + notarized + stapled (`packages/insomnia-inso/src/scripts/macos-pkg.sh`; workflow 279-310); Windows inso exe signing at 261. Homebrew cask bumps run on macOS runners (`.github/workflows/homebrew.yml:17, 66-71`).
- **Native modules are prebuilt per platform**: root `postinstall` downloads node-libcurl for Electron 43.2.0 (`package.json:36, 48`); CI installs the Node-ABI build for the CLI (`install-libcurl-node`, `package.json:37`); `scripts/install-x64-native-dependencies.ts` downloads macOS x64 `@node-llama-cpp` and `@reflink` tarballs manually for the universal build.
