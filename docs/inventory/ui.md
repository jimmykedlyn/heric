# UI

Inventory of the Insomnia renderer UI (`packages/insomnia/src`), read-only analysis of Insomnia 13.x on disk at `D:\Projects\Heric\Insomnia`. All paths below are relative to the repository root. React Router v7 flat-file routes (`packages/insomnia/src/routes.ts:1-11`), React 19, react-aria-components, CodeMirror 5, Tailwind v4 with CSS custom properties. Priorities: **P0** = core, must exist in Heric; **P1** = important, user-visible workflow; **P2** = polish/edge.

## Information architecture

- Route tree is generated by `flatRoutes({ ignoredRouteFiles: ['**/*.test.ts'] })` (`packages/insomnia/src/routes.ts:10-11`). Every file in `packages/insomnia/src/routes/` is a route module (~200 modules). There is no central route config.
- App shell: `root.tsx` renders `<Outlet />`, `<Toaster />`, `<Modals />`, `<VariableSourceTooltipHost />`, `<AppHooks />`, `<ImportModal />` (`packages/insomnia/src/root.tsx:804-812`). Root loader returns `{ settings, userSession, cloudCredentials }` and the shell owns `#graphql-explorer-container` / `#hints-container` mount points (`packages/insomnia/src/root.tsx:184-191`, `:255-256`).
- Top-level layout: organization page is a CSS grid with named areas `Header`, `Content`, `Statusbar` (`packages/insomnia/src/routes/organization.tsx:306-350`), defined as `'Header' / 'Content' 1fr / 'Statusbar' 30px` with columns `50px 1fr` (`packages/insomnia/src/ui/css/styles.css:88-94`). Header = logo + organization switcher + command palette + user actions (`organization.tsx:306-338`); Content = `<Outlet />` inside `RunnerProvider` (`organization.tsx:342-346`); Statusbar = sidebar toggle, header toggle and plan/user info (`organization.tsx:348-420`).
- Hierarchy: **Organization → Project → Workspace → (debug | runner | spec | test | environment | mock-server | mcp)**. Project and workspace pages are nested routes: `organization.$organizationId.project.$projectId.tsx`, `...workspace.$workspaceId.tsx` (`packages/insomnia/src/routes/`), with child routes `...workspace.$workspaceId.debug.tsx:482-493`, `.debug.runner.tsx`, `.spec.tsx`, `.test.tsx`, `.environment.tsx`, `.mock-server.tsx`, `.mcp.tsx`.
- Workspace page chrome: tab bar `<OrganizationTabList currentPage="debug" />` and `<WorkspacePaneHeader hasSettings />` rendered above the split panes, both hidden when the tutorial `?panel=` query is present (`packages/insomnia/src/routes/organization.$organizationId.project.$projectId.workspace.$workspaceId.debug.tsx:481-484`).
- Split layout is a nested `react-resizable-panels` pair: outer horizontal `PanelGroup autoSaveId="insomnia-sidebar"` containing the workspace content panel, inner `PanelGroup autoSaveId="insomnia-panels"` with direction `vertical` when `settings.forceVerticalLayout` or viewport ≤ 880px, otherwise `horizontal` (`debug.tsx:454-474`, `:485-493`). Panels are `pane-one` (request) and `pane-two` (response) (`debug.tsx:498`, `:568`). `autoSaveId` means the library persists panel sizes to browser storage.
- Request/response relationship: the request route (`...debug.request.$requestId.tsx`) is a child of the debug route; the debug route decides which response pane renders (gRPC, realtime, or HTTP) (`debug.tsx:563-579`). The response pane is only mounted when an `activeRequest` exists.
- Deep links: `window.main.on('shell:open')` handles `insomnia://` URLs in two places (`root.tsx:105`, `:448`): `app/auth/login` (`:455`), `app/alert` (`:458`), `app/open-folder` (`:467`), `app/import` (`:504`), `plugins/install` (`:546`), `plugins/theme` (`:580`), GitHub/GitLab OAuth callbacks (`:607-624`), `app/auth/finish` (`:625`), `app/open/organization`, `system-browser-oauth/redirect`. Pending links are stashed in sessionStorage and replayed after login (`root.tsx:761-768`).
- Navigation model over resources: `NAVIGATION_ROUTES` maps resource kinds to route ids and URL builders — `request-group`, `request`, `runner`, `mock-route`, `unit-test-suite`, `unit-test`, `workspace:mcp`, `workspace:mock-server`, `workspace:environment`, `workspace:design`, `workspace:collection`, `project:index` (`packages/insomnia/src/ui/hooks/use-insomnia-navigation.ts:36-112`); `getRouteIdForResource` resolves a model to a route id (`:175-190`).

Edge cases:
- P1: Loaders perform writes. The request loader updates `workspaceMeta.activeRequestId` and `requestMeta.lastActive` on every navigation (`packages/insomnia/src/routes/organization.$organizationId.project.$projectId.workspace.$workspaceId.debug.request.$requestId.tsx:116-126`), so simply opening a request mutates persistent state.
- P1: Workspace resolution requires `workspaceMeta`, base environment, cookie jar and (optionally) a mock server to exist; they are created on demand (`...workspace.$workspaceId.tsx:106-154`). A missing record is auto-created, not an error.
- P2: The sidebar toggle and header toggle live in the status bar (`organization.tsx:350-420`); the header is not collapsible via keyboard.
- P2: The `Header` area also hosts `HeaderInviteButton`, `HeaderPlanIndicator`, `HeaderUserButton` (`organization.tsx:157-168`), which are billing surfaces, not part of core client UX.

## Request editor behavior

- URL bar (`ui/components/request-url-bar.tsx`): method selector + one-line URL editor keyed by environment and VCS version, with a stable `historyKey` for undo state (`request-pane.tsx:103-116`). Enter sends/connects; a capture-phase `keydown` listener on `#sidebar-request-gridlist` sends on `metaKey+Enter` (`request-url-bar.tsx:260-272`, mac-only meta check). Shortcuts `request_focusUrl`, `request_send`, `request_toggleHttpMethodMenu`, `request_showOptions` are registered at `request-url-bar.tsx:283-298`.
- Send options dropdown: Generate Client Code, Send After Delay, Repeat on Interval, Download After Send, Send And Download. Interval and delay are driven by `useInterval`/`useTimeoutWhen` below the send effect (`request-url-bar.tsx:260-281`); the download path persists on RequestMeta (`downloadPath`, `insomnia-data/src/models/request-meta.ts:22`).
- Params tab: key-value editor or bulk edit text; toggling bulk writes `settings.useBulkParametersEditor` (`request-pane.tsx:216-235`); bulk mode passed to the editor at `:241`. "Import from URL" extracts the query string with `extractQueryStringFromUrl` (`:58`, `:10`) and patches URL + parameters. A rendered query-string preview is shown above the editor. Path parameters are derived with `getCombinedPathParametersFromUrl` (`:87`) and rendered separately; the dismissible path-parameter tip is persisted in localStorage (`dismissPathParameterTip`, `:53`, `:280`).
- Body tab: content-type dropdown (`ui/components/editors/body/body-editor.tsx:190`), branches for form-urlencoded (`:135-141`), form-data with file support (`:82`, `:143-144`), single file body (`CONTENT_TYPE_FILE`, `:91`, `:145-146`) which asks whether to update the Content-Type from the file extension (`:107-112`), GraphQL (`:64-66`, `:147-152`), and raw editor with prettify (`:161-170`). Event-stream and empty states are handled in the same component (`:32`, `:185-190`).
- Auth tab: delegated to `AuthWrapper` (`request-pane.tsx:22`, `:299-302`), covering inheritable auth types.
- Headers tab: read-only calculated rows `Accept: */*`, `Host: <calculated at runtime>`, `User-Agent: insomnia/<version>` (`ui/components/editors/request-headers-editor.tsx:30-33`); WebSocket requests use a different set (`:22-28`). Removing the last User-Agent header re-enables/keeps the read-only row (`:60-63`). Bulk mode uses `name: value` lines (`:111`).
- Scripts tab: pre-request and after-response editors with stable keys per request (`request-pane.tsx:372-404`). Docs tab: Markdown editor (`:408-420`).
- Editors are CodeMirror 5 (`ui/components/.client/codemirror/code-editor.tsx`, 1018 lines; `one-line-editor.tsx`, 695 lines). Editor state (undo history, scroll, cursor, selections) is cached by `historyKey` in a module-level LRU capped at 2000 entries (`ui/components/.client/codemirror/editor-state-cache.ts:32-64`) and restored on remount only when the model value has not changed (`:8-22`). Long lines are truncated with a "Show full value" widget; the operation is batched to limit reflows (`code-editor.tsx:120-155`). Read-only editors do not install the vim/emacs/sublime keymap so `Ctrl-A` keeps working (`code-editor.tsx:471-473`).
- Pane remount key: `uniqueKey` includes active environment id+modified, global environment id+modified, request id, git version, VCS version and active response id (`request-pane.tsx:82`); it forces editors to reload when the model source changes.

Edge cases:
- P1: `beautifyRequestBody` only acts in JSON/XML editors (`code-editor.tsx:380-385`) and is also registered by the GraphQL editor (`ui/components/editors/body/graph-ql-editor.tsx:305-317`). Both use the same global hotkey as `sidebar_focusFilter` (see Keyboard shortcuts).
- P1: Editor paste handling rewrites vault tag ids and can cancel cURL pastes (multi-line paste becomes one line in the one-line editor; `one-line-editor.tsx:224-247`).
- P1: Windows `{% file '...' %}` tags in environment JSON are escaped to preserve backslashes after parse (`ui/components/editors/environment-editor.tsx:42-44`).
- P2: `showAutocomplete` is not a global tinykeys binding; it is handled inside CodeMirror editors (`ui/components/.client/codemirror/extensions/autocomplete.ts:163`, `code-editor.tsx:536`, `one-line-editor.tsx:278`).

## Response viewer behavior

- Preview mode is persisted per request on RequestMeta (`previewMode`; default `PREVIEW_MODE_FRIENDLY` in `insomnia-data/src/models/request-meta.ts:36`, read in `ui/components/panes/response-pane.tsx:50`). Modes: friendly / source / raw (`insomnia-data/common-src/preview-mode.ts:1-17`). Error responses force source mode (`response-pane.tsx:261`).
- Size guards: `LARGE_RESPONSE_MB = 5`, `HUGE_RESPONSE_MB = 100` (`packages/insomnia/src/common/constants.ts:83-84`). Responses above 5 MB are blocked with "Show Anyway" / "Always Show" / "Save To File"; above 100 MB they cannot be shown and only save is offered (`ui/components/viewers/response-viewer.tsx:89-91`, `:186-210`). "Always Show" is a module-level flag that resets on app reload (`:36`, `:115`).
- Content sniffing: content-type is taken from headers, but HTML is detected heuristically and JSON is detected from the body (`response-viewer.tsx:135-161`); charset aliases are normalized (`:164-179`).
- Viewer branches: JSON in a CodeEditor with JSONPath filtering and clickable links (`:235-276`), images as data URLs (`:278-296`), HTML in an Electron `<webview>` with `<base href>` injection and JS disabled per `settings.disableHtmlPreviewJs` (`:298-307`, `ui/components/viewers/response-web-view.tsx:16-29`), PDF (`:309-315`), CSV via PapaParse (`:317-323`), multipart via IPC (`:325-341`), audio (`:343-353`), raw text (`:355-371`), and source fallback (`:373-392`).
- Response filter is persisted per request (`responseFilter`) with history capped at 10 entries (`ui/components/panes/response-pane.tsx:46-67`); filter input is applied through the CodeEditor (`response-viewer.tsx:253-270`).
- Response history dropdown groups responses by Just Now / minutes / today / week / older (`ui/components/dropdowns/response-history-dropdown.tsx:253-269`); selecting one patches `activeResponseId` (`:101`) and restores the associated request version.
- Save/download: `response-pane-utils.ts` uses `window.dialog.showSaveDialog` (`:27`) and `window.main.writeResponseBodyToFile` (`:41`); prettified JSON is serialized with `jsonPrettify` (`:68`). Save dialogs in the preview menu also remember the directory via `insomnia.lastExportPath` (`response-multipart-viewer.tsx:82`, `:104`).
- Export: HAR export through `window.main.exportHarCurrentRequest` (`preview-mode-dropdown.tsx:42`); HTTP debug export (`:83`, `:152-155`); "Export prettified response" disabled above 5 MB (`:139-144`).
- Password masking in environment/console views: random 4–11 mask characters, initially visible when `settings.showPasswords` (`ui/components/viewers/password-viewer.tsx:6-44`).

Edge cases:
- P0: `response_focus` selects the response body (registered at `response-viewer.tsx:121-124`).
- P1: CSV viewer's select-all listens to `Meta+A` only; `Ctrl+A` is not handled on Windows/Linux (`response-csv-viewer.tsx:25`) — platform bug.
- P1: If the response body was offloaded to disk but the buffer is missing, the viewer reports a filesystem read failure instead of rendering (see block ordering in `response-viewer.tsx:186-210`).
- P1: The `→ Mock` tab always renders `MockResponseExtractor` (tab id `mock-response`, `response-pane.tsx:225-231`, panel `:289-291`); its usefulness depends on the response being convertible to a mock.
- P2: Cookies tab counts `Set-Cookie` headers (`response-pane.tsx:148-150`); Tests tab count comes from `requestTestResults` (`:214-222`).

## Environments UI

- Three environment scopes: collection base + sub-environments (`baseEnvironment`, `subEnvironments`, loader `...workspace.$workspaceId.tsx:113-115`), project/global environments (workspaces with `scope: 'environment'`), and private environments stored locally. Active collection environment resolves via `workspaceMeta.activeEnvironmentId`, falling back to base (`:144-145`); active project environment via `activeGlobalEnvironmentId` (`:147-148`).
- Picker (`ui/components/environment-picker.tsx`): project-environment popover ("No Project Environment" + flattened global environments, `:119`, `:134-145`, `:195-260`) submits `set-active-global` (`:222`); collection-environment popover lists base + subs (`:285-330`) and submits `set-active` (`:317`) then emits `CHANGE_ACTIVE_ENV` (`:323`). Manage actions open the environments modal or the environment workspace editor (`:253-260`, `:298`). Project environments are created through `NewWorkspaceModal scope="environment"` (`:363-368`). The project picker is hidden for the Scratchpad project (`isScratchpadProject`, `:96`, `:168`).
- Manage modal (`ui/components/modals/workspace-environments-edit-modal.tsx`, 572 lines): preselects an environment by id (`:83-91`); creates shared or private sub-environments (`:175`, `:306`); duplicates/deletes (delete falls back to base); drag-reorders via `metaSortKey` midpoint arithmetic (`:239-255`); edits JSON data and KV pairs (`:193-220`). Switching is blocked when the selected environment has protected KV pairs (`hasProtectedKvPairs`, `:104`, `:473`).
- JSON editor (`ui/components/editors/environment-editor.tsx`): preserves key ordering (`json-order`), validates nested keys with `checkNestedKeys` (`:59-78`) and re-validates after restoring cached editor state (`:96-98`).
- KV editor (`ui/components/editors/environment-key-value-editor/key-value-editor.tsx`): blank trailing row is visual only until typing (`:120-140`); `SECRET` type is offered only in private environments when a vault key exists (`:167-169`); secret values are decrypted with `getRuntime().crypto.decryptSecretValue` using a base64-decoded vault key (`:120-141`); changing away from/into SECRET requires confirmation (`:283-311`); secret values are compared decrypted (`:355`).
- Environment mutation routes: create / delete / duplicate / set-active / set-active-global / update fetchers (`routes/...environment.{create,delete,duplicate,update}.tsx`, `...set-active.tsx`, `...set-active-global.tsx`); the edit modal submits `environment.update` (`workspace-environments-edit-modal.tsx:30`).

Edge cases:
- P0: Inheritance order is folder > collection > project; the tooltip states this explicitly (`environment-picker.tsx:32-40`, rendered at `:207`, `:303`).
- P1: Only one environment can be "active" per scope, but both collection and project environments are active simultaneously and merged during rendering.
- P1: Private environments and vault secrets are local-only; they never sync, and secret rows are unavailable without a vault key (`key-value-editor.tsx:167-169`).
- P1: Deleting the active environment falls back to the base environment.
- P2: The environments modal can be opened from anywhere via `uiEventBus OPEN_ENVIRONMENTS_MODAL` with a preselected environment (`ui/event-bus.ts:12-20`, `workspace-pane-header.tsx:44-64`). The modal closes/reopens when `location.key` changes (`workspace-pane-header.tsx:44-64`).

Edge cases:
- P0: `sidebar_focusFilter` and `beautifyRequestBody` share the same combination (Shift+Cmd+F / Ctrl+Shift+F) on both platforms (`hotkeys.ts:124-127` vs `:172-175`). A rebind is required to separate them, and no listener exists for `sidebar_focusFilter`.
- P0: `workspace_showSettings` is defined and displayed in settings but has no registered handler in the renderer (grep of `packages/insomnia/src` finds only the registry/description), so the shortcut does nothing.
- P1: Global shortcuts are bound on `window` in capture phase with no editable-target guard (`keydown-binder.ts:18-52`). - P1: `request_showOptions` sends/opens the dropdown rather than showing a modal; its handler toggles the send-options dropdown (`request-url-bar.tsx:296-298`).
- P2: `<Hotkey>` renders "Not defined" when no combination exists (`hotkey.tsx:43`); macOS combinations render as glyphs without `+` separators (`:37`, `:47`).
- P2: Keyboard display is platform-specific; rebinding one platform's array leaves the other platform's default untouched (`hotkeys.ts:212-218`).
