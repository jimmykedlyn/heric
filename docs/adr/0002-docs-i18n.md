# 0002 — Documentation i18n

- Status: accepted
- Date: 2026-11-10

## Context

The user documentation ships in English (source of truth), Portuguese
(pt-BR) and Spanish. Two options:

1. **Separate directory trees**, `docs/book/{en,pt-BR,es}`, each a complete
   mdBook with the same `SUMMARY.md` shape and file names.
2. **`mdbook-i18n-helpers`** with gettext: one English source tree, `.po`
   files per language, generated translations at build time.

## Decision

Use **separate directory trees**.

Reasoning: the translation workflow in this project runs as two parallel
translation subagents that rewrite prose naturally rather than mechanically.
Gettext `.po` files with fuzzy matching fight that workflow: every English
edit produces fuzzy entries the agents must reconcile, and the tree-of-files
model makes it trivial to verify that the three languages contain exactly the
same pages. The cost is that a structural change must be applied three times,
which the CI `docs` job enforces.

## Consequences

- `scripts/check-docs-structure.ps1` (and its shell twin) fails when the three
  trees diverge in file names or `SUMMARY.md` entries.
- Language selectors across `README`, `CONTRIBUTING` and the books follow the
  same pattern.
- Revisit if the documentation grows past the point where three trees are
  painful to keep in sync; gettext becomes attractive then.
